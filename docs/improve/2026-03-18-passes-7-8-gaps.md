## Gap 1: KPI Card Sparkline Tooltip Shows "Point 1" Instead of Category Label

**Visual**: `kpi-card`
**File**: `packages/kpi-card/src/visual.ts` lines 625, 758
**Impact**: HIGH — KPI Card is a flagship visual; sparkline tooltips show generic `"Point 1"`, `"Point 2"` labels instead of the actual category name (e.g., work week name, month, date).
**Root cause**: The `trend` array is extracted as bare numbers (line 247) with no corresponding category labels passed through. The `extractFromCategorical` method drops the `categoryColumn.values` labels.
**Fix**: Pass category labels alongside trend values. Change tooltip `displayName` from `` `Point ${idx + 1}` `` to the actual category label string.

## Gap 2: KPI Card Missing `contextmenu` Handler

**Visual**: `kpi-card`
**File**: `packages/kpi-card/src/visual.ts`
**Impact**: HIGH — KPI Card is the only visual (out of 31) without a `contextmenu` handler. Right-clicking does nothing instead of showing the PBI context menu. All other 30 visuals have this.
**Fix**: Add `contextmenu` event listener on the value row and sparkline elements that calls `this.selectionManager.showContextMenu(selectionId, { x, y })`.

## Gap 3: Stream-Graph Tooltip Missing Actual Value

**Visual**: `stream-graph`
**File**: `packages/stream-graph/src/visual.ts` lines 588-597
**Impact**: HIGH — When hovering a stream layer, the tooltip shows only "Series" name and optional "% of Total" but never the **actual numeric value** for that series. Users have no way to see the raw number.
**Fix**: Add the series total value to the tooltip data items:
```ts
tooltipItems.push({
  displayName: 'Total',
  value: formatWithSettings(total, this.settings.numberFormattingCard),
});
```

## Gap 4: Stream-Graph Y-Axis Tick Labels Ignore NumberFormattingCard

**Visual**: `stream-graph`
**File**: `packages/stream-graph/src/visual.ts` line 705
**Impact**: MEDIUM — Y-axis ticks use raw `Math.round()` instead of `formatWithSettings`. A user setting prefix "$" or display units "thousands" has no effect on axis labels while it does affect crosshair values and other formatted numbers. Inconsistent behavior.
**Code**: `.tickFormat((d) => String(Math.round(d as number)))`
**Fix**: `.tickFormat((d) => formatWithSettings(d as number, this.settings.numberFormattingCard))`

## Gap 5: Gantt Chart Tooltip Missing Duration and Separate Start/End Fields

**Visual**: `gantt-chart-pro`
**File**: `packages/gantt-chart-pro/src/visual.ts` lines 1087-1096
**Impact**: MEDIUM — Tooltip shows "Range" as one combined string (e.g., "Jan 5 - Feb 12") but does not show:
  - **Start Date** and **End Date** as separate tooltip rows
  - **Duration** (days/weeks between start and end)

These are standard fields in every major Gantt chart tool.
**Fix**: Add two more tooltip items:
```ts
{ displayName: 'Start', value: formatShortDate(task.startDate!, locale) },
{ displayName: 'End', value: formatShortDate(task.endDate!, locale) },
{ displayName: 'Duration', value: `${Math.ceil((task.endDate!.getTime() - task.startDate!.getTime()) / 86400000)} days` },
```

## Gap 6: No Per-Annotation Show/Hide Toggle

**Shared card**: `AnnotationFormattingCard` in `packages/core/src/shared-settings.ts`
**Affects**: 10 visuals (bar-chart-pro, morphing-area-chart, bump-chart, stream-graph, slope-chart, health-bar, bar-race, bullet-chart-pro, progress-bar-stack, animated-waterfall)
**Impact**: MEDIUM — The card has a global `showAnnotations` toggle but no per-slot show/hide. Once a user configures 3 annotations, they cannot temporarily hide annotation 2 while keeping 1 and 3 visible. They must clear the text to hide it.
**Fix**: Add `showAnnotation1`, `showAnnotation2`, `showAnnotation3` toggles (default: true) to `AnnotationFormattingCard`, and check them in `buildAnnotationConfig` before including each slot.

## Gap 7: Sankey Diagram Uses SVG `<title>` Elements Instead of PBI tooltipService

**Visual**: `sankey-diagram`
**File**: `packages/sankey-diagram/src/visual.ts` lines 819-847
**Impact**: MEDIUM — Sankey uses native SVG `<title>` elements for tooltips instead of `host.tooltipService`. This means:
  - Tooltip styling is browser-default (ugly, small, delayed)
  - No consistent tooltip appearance with other visuals
  - No tooltip pinning or drill-through support
  - Mobile/touch experience is degraded
**Fix**: Replace `append('title').text(...)` with proper `mouseover`/`mousemove`/`mouseout` handlers calling `host.tooltipService.show/move/hide`.

## Gap 8: Scatter-Bubble Uses Custom DOM Tooltip Instead of PBI tooltipService

**Visual**: `scatter-bubble`
**File**: `packages/scatter-bubble/src/visual.ts` lines 1468-1515
**Impact**: MEDIUM — Scatter-bubble creates its own `div.scatter-bubble-tooltip` elements positioned manually, bypassing PBI's `tooltipService`. This causes:
  - Inconsistent tooltip styling across the visual suite
  - No drill-through integration
  - Manual DOM cleanup needed (potential memory leaks)
  - No mobile touch support
**Fix**: Replace custom DOM tooltip with `host.tooltipService.show()` calls using `VisualTooltipDataItem[]`.

## Gap 11: No Show/Hide Toggle for Axis Tick Marks (Separate from Labels)

**Shared card**: `AxisFormattingCard` in `packages/core/src/shared-settings.ts`
**Affects**: All visuals with axes (~20 visuals)
**Impact**: LOW-MEDIUM — Currently `showXAxis` and `showYAxis` toggle the entire axis (ticks + labels + line). There is no way to:
  - Show axis labels but hide tick marks
  - Show tick marks but hide labels
  - Control tick mark length independently

Many axis-based visuals hardcode `tickSize(0)` (bar-chart-pro, stream-graph, box-plot, morphing-area-chart, dumbbell-chart), meaning tick marks are never visible even when the axis is shown.
**Fix**: Add `showAxisTickMarks` toggle to `AxisFormattingCard`, defaulting to `false` (matching current behavior).
