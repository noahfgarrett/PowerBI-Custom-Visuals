# SSM Explorer build and audit

Date: 2026-10-08. Release: 1.0.0.0. New package: `packages/ssm-explorer`.

## Delivered behavior

The new visual separates project identity, L1/L2 milestone membership, structural closest parents, and directional prerequisites. It supports multiple project selection, discipline and milestone filters, supporting context, iterative deep-chain traversal, branch expansion, search, canvas navigation, and a fixed details drawer. Author-controlled metadata fields are column-scoped in the Power BI Format pane. Existing Network Graph behavior was not changed by this work.

Only synthetic data was used for implementation tests, screenshots, and the development harness. The previously reviewed registry and SSM reference projects were kept read-only; their contents are excluded from the release.

## Audit corrections

- Normalize milestone scope before projecting a new project selection, preventing a false empty graph.
- Keep tags in different projects distinct and retain repeated milestone memberships without inflating physical-equipment counts.
- Retain metadata by node type when the same model column is bound to multiple details roles; deduplicate formatting descriptors by query name.
- Honor percentage, currency, and date model formats and the author's Connections visibility setting.
- Locate a searched node beyond the initial branch window without rendering the entire dataset.
- Emphasize assigned descendants when inspecting an L1 or L2 milestone.
- Restore focus after closing the drawer, enable Focus selected after node clicks, and clear stale drawer contents after data removal.
- Reset segmented-fetch state for a new dataset and keep native equipment identities separate from generated milestone identities.
- Correct overview-map coordinate mapping and verify pointer-centered zoom and canvas dragging.
- Collapse filters into a compact disclosure at small sizes; retain usable canvas and a scrollable overlay drawer at 320 × 280.
- Improve overview label readability and selected-node contrast. Navigation help stays behind a help control; normal operation avoids instructional paragraphs.
- Consolidate HTML rendering at one reviewed markup boundary. All registry-derived text and attributes are escaped; an injection fixture verifies that markup is displayed as text. The boundary has one documented, narrowly scoped lint exception.

## Field-binding correction — 1.0.1.0

The user subsequently reported that dragging columns into visualization field wells did nothing. The 1.0.0.0 capabilities mapping incorrectly required both Project and Equipment ID with `min: 1` in one condition. [Microsoft's mapping contract](https://learn.microsoft.com/en-us/power-bi/developer/visuals/dataview-mappings#conditions) permits only one role with a positive minimum per condition. The earlier browser and bundle tests injected completed DataViews and therefore did not exercise this host-side validation.

Version 1.0.1.0 removes both positive minima while retaining all maximum field counts. Any field can now be assigned first according to the mapping contract. The parser still requires Project and Equipment ID before constructing project-scoped nodes, and the setup message names the missing field using the same label as Power BI. The GUID is unchanged so the corrected package can replace the existing import.

Seventeen new capability-contract tests produced 16 failures against the original manifest and pass against the correction. Three additional Visual tests verify incomplete binding, completed binding, and field removal with Project, Equipment ID, or equipment metadata added first. All 52 SSM tests, repository TypeScript, and the production build passed. The package review now checks every visual for this invalid multi-minimum condition; all 33 packages pass that check. Direct drag-and-drop inside the user's Power BI host remains unobserved locally.
